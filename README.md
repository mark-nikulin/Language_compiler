Repository for compilators class

```
AST (JSON) -> компилятор -> SM-код (JSON) -> стековая машина -> Output
    |
    +-> интерпретатор AST -> Output
```

Программа приходит как JSON AST. Её можно выполнить сразу по дереву или скомпилировать
в код стековой машины и выполнить его. Результат у обоих способов одинаковый для
поддерживаемых компилятором конструкций, это проверяет команда `check`. `switch`
пока выполняется только интерпретатором AST.

## Запуск

```
python3 main.py compile    program.json
python3 main.py run-ast    program.json "1, 3"
python3 main.py run-sm     program.json "1, 3"
python3 main.py run-smfile code.json "1, 3"
python3 main.py check      program.json "1, 3"
python3 -m unittest discover tests
```

## Как устроено

Разбор JSON, построение AST, компиляция и выполнение AST обходят дерево циклом,
а нерешённые задачи лежат в списке. Рекурсивные вызовы функций языка также
выполняются через явный стек задач, без рекурсивных вызовов интерпретатора Python.

Значение это число или указатель. Строки, массивы и S-выражения живут в куче,
переменная хранит ссылку на них, поэтому после `b = a` оба имени указывают на один массив.

У каждого оператора есть метка выхода: место, куда нужно перейти после него. `LABEL`
ставится, только если на эту метку есть переход. Например, `if` без `else` превращается
в `[c] ; JZ X ; [t]`.

SM-код это JSON-массив инструкций: `"READ"`, `{ "ST": "a" }`, `{ "CONST": 1 }`,
`{ "JZ": "L_end_0" }`. Для кучи есть `STRING`, `ARRAY n`, `ALOAD`, `ASTORE` и `ALEN`.

Ошибки печатаются в виде `ERROR: variable "y" is undefined`.
Код возврата: 0 если всё хорошо, 1 если ошибка в программе L0, 2 если входные данные
некорректны, 3 если `check` нашёл расхождение.

## S-выражения и списки

Вход проекта — JSON AST, а не текст языка. Примеры выражений:

```json
{"sexp": {"tag": "Pair", "args": [{"const": 1}, {"const": 2}]}}
{"list": [{"const": 1}, {"const": 2}, {"const": 3}]}
{"binop": ":", "left": {"const": 1}, "right": {"list": []}}
{"char": "A"}
```

Первое выражение создаёт `Pair(1, 2)`. Литералы и образцы списков при построении
AST превращаются в обычные `cons` и `nil`; отдельного исполнения списков нет.
Аргументы доступны через существующее
`elem`, их можно менять через `set`, а число аргументов получить через `length`.
`char` обозначает однобайтовый символ и вычисляется в его числовой код, как и
элемент строки. Список представлен узлами `cons(head, tail)` и `nil`; корректный
список выводится как `{1, 2, 3}`, пустой — как `{}`. Другие S-выражения
выводятся как `Pair(1, 2)`, а конструктор без аргументов — как `Pair`.
Циклические ссылки при выводе обозначаются `<cycle>`.

Компилятор создаёт команду `SEXP` с именем и числом аргументов. Например,
`Pair(1, 2)` компилируется в `CONST 1`, `CONST 2`, `SEXP "Pair" 2`.
В JSON-коде машины эта команда записывается как `{"SEXP": ["Pair", 2]}`.
Аргументы снимаются со стека в обратном порядке, а на стек кладётся ссылка
на новый объект. Команда `BINOP :` создаёт `cons`.

Все шесть операций сравнения работают со значениями всех видов, включая
разделяемые и циклические структуры. Разные виды упорядочены так: число,
строка, массив, S-выражение. Строки сравниваются по байтам, массивы —
лексикографически, S-выражения — сначала по имени конструктора, затем по
аргументам. При обходе повторная пара ссылок считается уже сопоставленной;
таким образом сравнение циклических структур завершается. Арифметические
и логические операции по-прежнему принимают только числа.

## Сопоставление с образцом в AST-интерпретаторе

`switch` вычисляет выражение один раз и выполняет первую подходящую ветку:

```json
{"switch": {
  "expr": {"var": "xs"},
  "branches": [
    {"pattern": {"list": []}, "body": {"write": {"string": "nil"}}},
    {"pattern": {"cons": [{"var": "x"}, {"var": "ys"}]},
     "body": {"write": {"var": "x"}}}
  ]
}}
```

Доступные образцы:

- `"_"` — любое значение; `{"var": "x"}` — связать имя со значением.
- `{"const": 42}`, `{"char": "A"}`, `{"string": "text"}` — литералы.
- `{"as": {"name": "x", "pattern": ...}}` — связать значение целиком и
  проверить вложенный образец.
- `{"array": [...]}`, `{"list": [...]}` — массив или полный список заданной
  длины; `{"cons": [head, tail]}` — голова и хвост списка.
- `{"sexp": {"tag": "Pair", "args": [...]}}` — конструктор и его аргументы.
- `{"type": "int"}`, `"string"`, `"array"` или `"sexp"` — проверка вида.

Одинаковые имена внутри одного образца должны соответствовать равным значениям.
Связанные имена видны только внутри выбранной ветки и затеняют внешние имена;
присваивание другим именам изменяет ближайшую внешнюю переменную или создаёт
новую в текущем вызове функции (вне функции — глобальную). Вложенные `switch`
создают собственные области видимости. Если ни одна
ветка не подошла, возникает ошибка `ERROR: no matching switch branch`.
Компиляция `switch` в SM пока не поддерживается; компилятор сообщает об этом явно.

Пример из задания переписан в двух вариантах: [встроенный список](examples/list_switch.json)
и [S-выражения](examples/sexp_switch.json). Оба запускаются через `run-ast`, например:

```sh
python3 main.py run-ast examples/list_switch.json 0
python3 main.py run-ast examples/sexp_switch.json 0
```

## Области видимости и функции

`scope` создаёт область видимости для объявленных переменных и функций. Вход
по-прежнему задаётся в JSON AST; отдельного парсера текстового языка нет.

```json
{
  "scope": {
    "vars": ["result"],
    "functions": [
      {
        "name": "double",
        "params": ["x"],
        "body": {
          "return": {
            "binop": "*",
            "left": {"var": "x"},
            "right": {"const": 2}
          }
        }
      }
    ],
    "body": {
      "seq": {
        "left": {"assn": {"dst": "result", "src": {
          "call": {"name": "double", "args": [{"const": 13}]}
        }}},
        "right": {"write": {"var": "result"}}
      }
    }
  }
}
```

Поля `vars` и `functions` можно опустить, если они пусты; поле `body`
обязательно. Элементы `vars` и параметры функции — непустые, неповторяющиеся
имена; имена функций в одной области тоже не должны повторяться. Список
`args` у вызова обязателен, в том числе пустой для функции без параметров.

Объявленные переменные сначала не инициализированы. Они затеняют внешние
переменные и существуют до выхода из области. Присваивание ищет ближайшее
объявленное имя по лексической цепочке. Внутри функции неизвестное имя создаётся
в области текущего вызова; вне функции — в глобальной области. Поэтому для
затенения уже существующего внешнего имени его нужно указать в `vars` или
параметрах. Ветвь `switch` по-прежнему создаёт отдельную область для имён
образца. Имена функций и переменных находятся в разных пространствах имён.

Все функции `scope` видны друг другу и самим себе, поэтому поддерживается как
обычная, так и взаимная рекурсия. Функция видит переменные и функции области,
в которой она объявлена, а не локальные переменные вызывающей функции.
Каждый вызов получает собственные ячейки параметров; аргументы вычисляются
слева направо. Числа передаются как значения, составные объекты — как указатели:
изменение общего массива или S-выражения видно вызывающему коду.

`return` вычисляет выражение, завершает ближайший вызов функции и возвращает
результат в выражение вызова. При этом выходят и вложенные области `scope` и
веток `switch`, пропускается остаток тела и отменяются ожидающие итерации
циклов. `return` вне функции, неизвестная функция, неверное число аргументов
и завершение тела функции без `return` являются ошибками программы.

Функции объявляются в `scope` и вызываются по имени: как значения их передавать
или возвращать пока нельзя. `scope`, вызовы и `return` поддерживаются как
AST-интерпретатором, так и компилятором и стековой машиной. При этом программы
со `switch` по-прежнему выполняются только через `run-ast`.

Компилятор для параметров и объявленных локальных переменных использует адреса
`["ARG", глубина, номер]` и `["LOC", глубина, номер]`: глубина показывает,
сколько лексических областей нужно пройти наружу. Для остальных имён используется
`["NAME", имя]` и поиск через окружение во время выполнения. Обычные глобальные
имена в SM-программах без областей сохраняют прежний формат `{"LD": "x"}`.
`ENTER` создаёт область и регистрирует функции, `LEAVE` закрывает область;
`PRECALL` проверяет функцию и число аргументов до их вычисления, `CALL` создаёт
кадр вызова, `RETURN` восстанавливает вызывающего и возвращает значение, `END`
сообщает об отсутствии `return`. `RESOLVE` создаёт нужную ячейку имени до
вычисления правой части присваивания. Машина сохраняет лексическое окружение
объявления функции, поэтому вложенная функция может изменять внешнюю переменную.

Например, инструкция с локальным адресом в JSON выглядит так:
`{"LD": ["ARG", 0, 0]}`. `compile-text` и `run-smfile` поддерживают эти
операнды и декларации областей в текстовом формате с аргументами JSON.
Статическая проверка глубины стека пока не реализована.

В [examples/nested_functions.json](examples/nested_functions.json) вложенная
функция изменяет локальную переменную внешней функции. Обе реализации выводят
`8`, их результаты можно сравнить командой:

```sh
python3 main.py check examples/nested_functions.json 0
```

### Пример: рекурсивное вычисление выражения

В [examples/recursive_eval.json](examples/recursive_eval.json) пример из
задания представлен S-выражениями и вычисляется рекурсивной функцией со
`switch`. Схематически, в привычной записи, логика такая:

```text
function eval(expr) {
  switch (expr) {
    case Num(n)         -> return n
  | case Add(left, right) -> return eval(left) + eval(right)
  | case Mul(left, right) -> return eval(left) * eval(right)
  }
}

write(eval(Add(Num(2), Mul(Num(3), Num(8)))))
```

Это поясняющий псевдокод; исполняемая версия — JSON-файл. Неизвестный вид
выражения приводит к ошибке отсутствующей ветки `switch`. Запуск:

```sh
python3 main.py run-ast examples/recursive_eval.json 0
# 26
```

В исходном варианте задания `26` оставалось на вершине явно организованного
стека `st_x`; здесь функция сразу возвращает вычисленное значение.
